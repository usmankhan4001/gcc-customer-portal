# v2.3 — Serve & Retain Clients

**Status**: planned   **Goal**: run existing clients with less staff effort and no missed renewals.

## Features

### F3.1 Renewal engine
Build from scratch: nothing creates `renewals` rows today, the admin renewals page is mock data and `sendRenewalReminder` has no callers (see `docs/ai/features/renewals.md`). Needs a creation rule (e.g. at paid order + licence term), a scheduler, and idempotent sends.
- Cron-driven reminders at 60/30/15 days from `renewals`; one-click renewal invoice via Stripe checkout; status updates on payment webhook.
- AC: each reminder sends once; paying creates the next renewal record; failed payment keeps status open and alerts staff.

### F3.2 Multi-company switcher and import
- "My companies" switcher; "Bring your company" wizard to import an existing entity (details + documents).
- AC: data and documents are always scoped to the selected company; import creates a staff review task.

### F3.3 Customer 360 and task SLAs (admin)
- One page per client: companies, orders, documents, milestones, messages, score, timeline. Tasks with owner and due date; overdue alerts.
- AC: page only for admins (`requireAdmin`); overdue task triggers one alert per day max.

### F3.4 Upsell suggestions
- Rule-based suggestions from gaps and score (missing tax registration -> accounting, no bank account -> banking, visa expiring -> visa renewal), surfaced in app and admin.
- AC: a suggestion is shown only when its rule matches; dismiss is remembered.

### F3.5 Client timeline with estimated dates
- Milestone tracker shows estimated completion dates and last update; staff edit estimates.
- AC: changing an estimate notifies the client once.

## Dependencies
v2.0 push, v2.1 calendar/locker/scoring; Stripe webhook idempotency (F0.2).

## Out of scope
Client satisfaction pulse, bulk actions, team access.
