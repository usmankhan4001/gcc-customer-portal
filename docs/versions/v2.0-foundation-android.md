# v2.0 — Foundation & Android Shell

**Status**: planned   **Goal**: remove live risks, then ship an installable Android app on the Play internal track.

## Features

### F0.1 JWT secret hardening **[P]**
- Production refuses to start (or to sign/verify) without `JWT_SECRET`; no hardcoded fallback in `auth.ts` or `env.ts`.
- AC: unit test proves missing secret throws when `NODE_ENV=production`; dev still works with a documented dev value.

### F0.2 Admin seed endpoint and webhook audit **[P]**
- `/api/admin/seed-admin` is disabled or locked behind a one-time secret/env flag in production.
- Stripe and WhatsApp webhooks are idempotent (duplicate event ids processed once).
- AC: tests for duplicate webhook delivery; seed route returns 404/403 in production.

### F0.3 Mobile token auth **[P]**
- Bearer access + refresh tokens for the app, alongside the existing cookie session for the web.
- Refresh rotation, revoke on logout, device list per user.
- AC: login via WhatsApp OTP returns tokens; expired access token refreshes; revoked refresh token fails.

### F0.4 FCM push + device tokens
- `device_tokens` table (user, platform, token, last_seen). `sendPushToUser` fans out to FCM and keeps web push as fallback.
- AC: sending to a user with one Android token and one web subscription delivers to both; invalid tokens are pruned.

### F0.5 Capacitor Android shell
- Native features from day one: push, camera, biometric lock, deep links (WhatsApp link -> in-app screen).
- Play readiness: privacy policy page, Data Safety answers, in-app account deletion.
- AC: signed AAB builds; internal-track install works; deep link opens the right screen; delete-account removes user data.

### F0.6 Events and consent
- `events` table (user/anon id, name, props, ts) and `consents` table (user, channel, status, source, ts).
- AC: tools emit `tool_used`/`result_viewed`; no outbound message is sent to a channel without a granted consent row.

### F0.7 Security hardening round 2 **[P]**
Done so far: JWT secret (spec 001), onboarding takeover / OTP leak / fixed OTP / seed-admin (spec 002). Remaining, from the feature docs:
- `getServerSession()` must verify the cookie itself instead of trusting `x-user-*` headers (good-standing route is spoofable).
- OTP and password-login attempt limits and rate limiting; stop logging OTP and OTP hashes.
- WhatsApp webhook: require `WHATSAPP_APP_SECRET`, dedupe on `message.id`, fix the KYC reference regex and phone matching.
- Stripe webhook idempotency (event id or status guard); handle failed/expired/refunded events.
- Validate the `redirect` param; remove the email leak in lead capture; authenticate `/api/push/unsubscribe`; lock down `/api/pdf/generate`; escape email HTML.
- Share links: hash tokens, add revoke and optional password. Vault upload: allow-list file types, create the new row only after upload.
- Make `docker-entrypoint.sh` fail loudly when migrations fail; unify `/api/admin/kyc/review` with `requireAdmin()`.
- AC: each item has a test that fails on the current code.
