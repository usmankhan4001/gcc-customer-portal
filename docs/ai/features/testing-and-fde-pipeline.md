# Feature: Testing and the FDE (spec-to-commit) pipeline

**Slug**: testing-and-fde-pipeline   **Area**: [platform-and-infra](../modules/platform-and-infra.md)   **Status**: partial   **Last verified against code**: 2026-10-30

## What it does
Two things: (1) the verification stack (vitest unit/route tests, a manual HTTP smoke script, and `npm run verify` which CI runs), and (2) a local "FDE" pipeline that takes an approved spec and drives Claude Code sub-agents to implement it, verify it, check docs, review it, and make a LOCAL commit. Test coverage is thin: 37 passing tests in 6 files, concentrated on auth hardening, persona logic and the pipeline helpers. Nothing tests webhooks, messaging, vault, checkout, middleware or UI.

## Entry points
- `npm test` (`vitest run`), `npm run typecheck` (`tsc --noEmit`), `npm run verify` (typecheck && test && `next build`), `npm run test:routes` (needs a running server), `npm run docs:ai`, `npm run fde -- <spec> [--dry-run] [--max-fix=N] [--allow-protected]`.
- Slash commands: `/new-spec`, `/build`, `/document-feature` (`.claude/commands/`).
- CI: `.github/workflows/ci.yml` runs `npm run verify` (see [deploy-and-ci](deploy-and-ci.md)).

## Request / response contract
none. CLI contract: `npm run fde -- docs/specs/<NNN-slug>.md [--dry-run] [--max-fix=2] [--allow-protected]`; env `CLAUDE_BIN` (default `claude`), `FDE_BUDGET_USD` (default `5`, passed as `--max-budget-usd`), `FDE_MODEL`. Exit 0 on success or `--dry-run`; any `die()` exits 1. Reviewer must end with one JSON line `{"verdict":"pass|fail","issues":[...]}`.

## Step-by-step flow (`scripts/fde/run.mjs`)
1. Parse args (`:10-14`); require an existing spec file whose `**Status**:` is `approved` (`parseStatus`, `:26-29`); branch name `feature/<spec basename>`; create `.fde/runs/<iso>-<base>.log` (`.fde/` is gitignored, `.gitignore:47`).
2. `--dry-run` prints the plan and exits (`:62-66`), no model call.
3. Refuse a dirty tree (ignoring lines containing `.fde/`) (`:68`); `git switch` or `switch -c` the feature branch; record base SHA.
4. `implement()` = `claude -p --append-system-prompt <implementer.md without frontmatter> --permission-mode acceptEdits --allowedTools "Read,Edit,Write,Glob,Grep,Bash(npm run verify),Bash(npm run typecheck),Bash(npm test:*),Bash(npm run db:generate),Bash(npm run docs:ai),Bash(git status:*),Bash(git diff:*)" --max-budget-usd N`, prompt on stdin (`:48-58`).
5. `verifyLoop`: run `npm run verify`; on failure and rounds < `maxFix`, call implementer with the last 6000 chars of output; after `maxFix` failed rounds die with the tree left on the branch (`:82-92`).
6. Docs gate (`:94-98`): requires `docs/ai/features/<base>.md` AND that `docs/ai/FEATURES.md` contains the base string; otherwise asks implementer to create them from `_TEMPLATE.md`, then dies if still missing.
7. Protected gate (`:100-102`): files from `git status --porcelain` (path = `line.slice(3)`) matched against `PROTECTED` (`lib.mjs:4-13`): `src/lib/{auth,admin-auth,session,stripe,r2}.ts`, `src/middleware.ts`, `src/app/api/(checkout|vault|webhooks)/`, `Dockerfile`, `docker-entrypoint.sh`, `.github/workflows/`, `.claude/`, `scripts/fde/`. Hit without `--allow-protected` -> die.
8. Reviewer (`:104-111`): read-only tools (`Read,Glob,Grep,Bash(git diff:*),Bash(git log:*),Bash(git status:*)`), default permission mode. No parsable verdict -> die. `fail` -> implementer fixes the listed issues, then `verifyLoop` again.
9. Finish (`:113-118`): rewrite spec `**Status**: approved` -> `shipped`, `git add -A`, `git commit -m "feat(<base>): implement spec ..."`. Never pushes.

## Data
No DB. Artifacts: `.fde/runs/*.log`, spec file Status field, new branch and commit. `docs/ai/CODEMAP.md` regenerated by `codemap.mjs` (pages from `page.tsx`, API routes from `route.ts` by regex `export async function (GET|POST|PUT|PATCH|DELETE)`, tables from `pgTable(...)`, lib exports); it ignores `route.tsx` so `api/companies/good-standing` is missing (CODEMAP lists 30 routes), and ignores `export const GET =` styles.

## Business rules and constants
- Defaults: `maxFix=2`, budget `$5` per agent call, per-call `maxBuffer` 128 MB.
- `tests/auth-routes.test.ts` covers exactly: onboarding takeover guard (existing user row, no session -> 409, no update, no cookie); send-otp in production with WhatsApp unconfigured -> 502 and body without `devOtp`/6 digits; verify-otp production rejects `123456` -> 400; seed-admin in production without token -> 404 and no insert. It uses a chainable fake `db` (`from/where/orderBy/limit/values/set/returning` return the chain, awaiting yields `rows`) and mocks `next/headers` and `@/lib/posthog-server`.
- `scripts/test-routes.js` (not in CI): 32 GET routes (8 public pages, `/tools` + 10 tools, 5 portal, 5 admin, 3 APIs: `/api/countries`, `/api/tax-rules?jurisdiction=uae`, `/api/auth/session`) against `http://localhost:${PORT||3005}`. OK means status 200-399; additionally `/api/auth/session` may be 401 and `/api/tax-rules` may be 500 (treated as "DB unreachable" ok). It does not follow redirects, checks no body, has no request timeout, exit code 0 only if all pass.

## Auth, permissions, security
- `.claude/settings.json` allows `npm run verify|typecheck|build|test:routes|db:generate`, `npm test:*`, `git status|diff|log`; denies `Read(./.env.local)`, `npm run db:migrate`, `git push --force|-f`.
- The protected-file gate is detective, not preventive: the implementer is launched with `acceptEdits` and `Write/Edit` anywhere, and the check runs only after verify. The review-fix `implement()` at step 8 runs AFTER the protected gate and is never re-gated, so it can modify protected files and commit them (`run.mjs:104-114`).
- Gaps vs AGENTS.md section 5: `PROTECTED` omits `src/lib/jwt-secret.ts`, `src/lib/auth-policy.ts`, `src/app/api/auth/**`, `src/app/api/admin/**`, `src/lib/db/schema.ts`, `drizzle/**`, `src/lib/{whatsapp,email,push}.ts`.
- The pipeline commits with `git add -A`; `.fde/` is ignored but any stray file (e.g. `.env` copies, which are gitignored) is the only protection.

## Failure modes and edge cases
- Agent process failure (`claude` missing, nonzero exit) -> die; tree may be dirty on the feature branch; rerun requires clean tree.
- Reviewer fail gets exactly one fix round and no second review.
- `slice(3)` on `git status --porcelain` mangles rename entries (`old -> new`) and quoted paths with spaces; protected hits could be missed. Untracked directories appear as `dir/` entries.
- Docs gate checks only substring presence in `FEATURES.md`, not content quality.
- `verify` includes `next build`, so each fix round is slow and needs `DATABASE_URL`/`JWT_SECRET` env; CI sets placeholders, a local run uses `.env.local` that agents cannot read.
- Tests that import routes rely on module-level mocks; adding a new import of `@/lib/db` in a route without mocking will try to open a real connection (postgres-js is lazy, so only a query fails).

## Known bugs and gaps
- No tests for webhooks, messaging, vault, checkout, admin routes, middleware, components or SW; no coverage measurement; vitest env is `node` only.
- CI skips `npm run lint` and `test:routes`; Node 22 in CI vs 20 in the image.
- Review-fix round bypasses the protected-file gate (`run.mjs:107-111`); gate list incomplete (above).
- `CODEMAP.md` omits `route.tsx` handlers (`codemap.mjs:19`).
- Security log finding surfaced while running tests: `send-otp/route.ts:83` logs the plaintext OTP whenever WhatsApp is unconfigured, even with `NODE_ENV=production` (the test output printed it), and `verify-otp` logs expected/received hashes. Report to owners (auth zone).
- `CLAUDE.md` tells agents to run `npm run test:routes`, which needs a live server and DB; `verify` is the real gate.

## Change guide
- Add a test: sibling `*.test.ts` for `src/lib/**` logic; route tests go in `tests/` and should mock `@/lib/db` (copy the chain stub) and `next/headers`. Stub env with `vi.stubEnv` and `afterEach(vi.unstubAllEnvs)`.
- Change pipeline behavior only with human approval (`scripts/fde/**`, `.claude/**` are protected). Keep `lib.mjs` pure and covered by `tests/fde.test.ts`.
- When adding a feature: write `docs/ai/features/<slug>.md` from `_TEMPLATE.md` and add a `FEATURES.md` row, or the pipeline's docs gate fails.
- Android/FCM readiness: add Capacitor/Android checks to CI as a separate job (Gradle build, `cap sync`), unit-test the token-auth routes with the same chain-stub pattern, and extend `PROTECTED` with any new auth/token files. Add mock-FCM tests for the per-platform branch in `sendPushToUser`. Keep `npm run verify` web-only so web PRs stay fast.
